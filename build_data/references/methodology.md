# Methodology

数据构建是运行在**代理观测**上的 POMDP 闭环:数据集真实质量是不可直接观测的 S,
audit / judge 是有噪声的 O,数据修复是 A,唯一的真实 R 是训练后的下游指标。
任何数据集(无论 VQA 还是 embedding 线)必须按序回答:
**① R 总账是什么(什么算好)→ ② 语料包络能否承载(能不能做好)→ ③ 监督信号如何定义(什么算对)**。
领域特有内容(R 指标、gate、污染词表、假负例规则)不写在本文,放在 `profiles/<domain>.yaml`。

## 0. R 总账与观测金字塔(闭环的地基)

**R 总账**:所有质量指标必须登记进 profile 的 `metrics`,权重之和 = 1。指标分两类:
- `true_r`(如下游 Recall@10):唯一真实 R,天级/千元级,只在里程碑观测;
- 代理指标(假负率、仿真度、配比…):只为 true_r 服务,**它的合法性由它与 true_r 的相关性决定**。

Proxy ≠ 目标:闭环日常运行在代理 R 上,代理 R 与真实 R 的偏差本身是一个隐藏状态,
因此需要在 cheap proxy 与 expensive true R 之间插入中间观测层(金字塔):

| 层 | 工具 | 成本/节奏 | 回答什么 |
|---|---|---|---|
| proxy | audit 脚本(auto 项) | 免费·秒级,每批 | 格式/规则类错误是否清零 |
| judge | VLM-as-judge 抽检相关性/仿真度 | 元级·分钟,每批次 | 代理 R 与真实 R 的偏差有没有变大 |
| true_r | 训练后下游 eval | 千元·天级,仅里程碑 | 权重、阈值、甚至指标本身是否该改 |

**obs 的输出是信念(O)不是真值(S)**:audit 的 `[auto]` 项只是机器可测的下限,
`[manual]` 项是低频高成本的人工观测通道——两级共同逼近 S,任何时候不要把 audit 通过当成质量合格。

## 0.5 语料能力包络裁决(meta-R gate)

定义 A(堆样本/修数据)之前,先像 AOP 本体裁决那样问:**这份语料的能力包络能否覆盖目标 R?**
`R 可达 ⟺ 目标质量 ∈ 语料承载结构`——数据救不了语料不足,正如智能救不了结构不足。
profile 的 `capability_gates` 逐条声明:每条轴/样本类的承载结构是否存在、
ground truth 是否有权威通道、覆盖面是否够 query 分布。**gate 未过:降权、弃用或缩小 R 承诺,不硬堆样本。**
这是最贵、最隐蔽错误的防线(典型:缺极难负承载结构的轴退化为字符串匹配,放量后才发现)。

## 1. 什么算"对"?

**监督信号由下游任务定义**:一项标注是正确的,当且仅当它对应真实用户场景中的正确行为。

- **Embedding 线——什么算相似**:两项相似 ⟺ 同一条真实 query 应当同时检索到它们。枚举全部相似轴(内容/实体 ID/结构层级……),每条轴对应一类样本;轴的定义属于领域 profile。
- **VQA 线——什么算好答案**:答案是真实用户想得到的,且**可验证**。答案若声称来自图像内容,必须真实可见(跨模态合法性判据:文本特征能锚定图像,当且仅当它出现在图里;只在文件名/元数据里的信息不合法)。可验证性不足的样本要么重写要么丢弃。
- **单向量妥协(embedding)**:一个 embedding 承载多条轴。轴冲突时(内容相同、机型不同)模型只能学加权混合。解法是让区分性特征**视觉可见**(如 banner 注入),否则模型会抓视觉代理特征(logo、版式、字体)充当该轴。
- **开放轴注册表(活/冻结)**:相似轴不是封闭枚举——训练评测暴露的新失败模式,注册为新轴;
包络 gate 未过的轴标记降权/弃用。pipeline 阶段同样标注活/冻结:确定性阶段(渲染/去重/组装/静态检查)冻结成脚本,
只有需要运行时智能的阶段(caption/query/语义审计)用 LLM——在冻结层引入智能、或在活层硬写规则,都是错位。
- **假负例是最贵的错误(embedding)**:对比学习假设所有未配对项都不相似。凡业务上判定为实质等价的样本对(同流程相邻步骤、同实体的不同视图、同内容的双语版本……)互为难负 = 直接教模型把该拉近的推开。**哪些对算实质等价由 profile 的 `fake_negative_rules` 声明**;训练期 `INFONCE_MASK_FAKE_NEGATIVE` 只是兜底,数据侧规避成本更低。
- **答案泄漏是最贵的错误(VQA)**:问题里含答案线索(整句复述、唯一提示词)的样本教模型走捷径而不理解图像。audit 以"答案子串出现在问题中"作机器检测下限,语义级泄漏靠 `[manual]` 抽检。

### 1.5 负例经济学(embedding)

负样本的**数量 ≠ 质量**:负例的价值在于"堵住已观测到的失败模式",不在堆量。堆量
会依次走过拟合→过弱→平衡点的曲线,而真正治假阳的是**定向硬负例**——数量 +1,
但精准针对一个真实失败 case。

- **低信息页是假阳的通用病源(hubness)**:空白图、封面、目录、章节首页这类结构性低信息页,
  embedding 退化为质心附近向量,对大量 query cosine 偏高。它们"既不正也不负地留在库里"
  = 未校准,推理时是定时炸弹。**必须显式作负例(且跨多 query 复用),不能"留空"。**
  在 profile 的 `fake_negative_rules` 之外的负例选取策略中优先覆盖。
- **辅助文本的稀释效应**:caption-rich 训练形态下,文本 token 数与语义方差远超图 token,
  pooling 后 embedding 主要由 caption 决定,图通路几乎未被锻炼;推理遇纯图即退化。
  **训练形态必须与推理形态对齐**:训纯图检索就不给 caption 兜底,反之亦然。
- **定向负例的来源纪律**:发现具体失败 case(如"空白图高响应""某 query 错误命中首页")
  后,针对该 case 类造负例,比加量更省更准(配合 §2 的失败 case 驱动原则)。

## 2. 通用训练原则(按重要性排序)

1. **Proxy ≠ 目标**:InfoNCE margin / SFT loss 都是代理指标,优化对象是仿真真实 query 的 eval 指标(Recall@k、答案准确率)。
2. **噪声代价非线性**:对比学习中一条假负例污染整个 batch;SFT 中一条错误答案直接写入模型输出分布。宁缺毋滥。
3. **Batch 内梯度耦合(embedding)**:易负 → 梯度趋零;假负 → 方向错误;"视觉相似但语义不同" → 信噪比最高的监督信号。
4. **训练 query 分布 = 模型学到的能力分布**:query 与推理时用户问法偏离多少,上线就崩多少。模板句式会产生"句式指纹"而非语义。两条线同理:VQA 的问题也要仿真真实问法,并按来源/轴均衡覆盖。
5. **Shortcut 是默认行为**:任何与语义无关却一致出现的特征(文本模式、视觉版式)都会被当作信号,除非主动压制。具体黑名单由 profile 的 `pollution_patterns` 提供。
6. **域适配微调防遗忘**:基于预训练基座时混入通用数据做 replay。
7. **评测驱动**:按**来源单元**切分 eval/train 防泄漏(如按文档、按场景切,而非随机切样本);先 1k–2k 高质量样本建基线,放量至指标 plateau 即停。
8. **多样性 > 同源堆量**:跨域、跨图类型(整页/插图/爆炸图…)、跨 query 风格的多样性,
   对泛化的边际收益高于同源扩规模。扩量前先问:新数据的**差异化维度**是什么?
   与已有样本同维度加量,不如换一个维度补短板。

## 2.5 失败 case 驱动(修复动作的优先级)

数据修复动作(A)有三个来源,优先级从高到低:

1. **失败 case 倒推(杠杆最高)**:每个具体假阳/坏例直接指向一个数据缺陷
   ("空白图高响应"→缺低信息页负例;"短 query 命中首页"→query 风格单一 + 枢纽页未压制)。
   **别先调超参,先拿失败 case 倒推数据缺什么**——补数据往往比调 lr/epoch 更有效,
   因为训练超参改变的是优化过程,数据缺陷才是监督信号本身的错误。
2. **audit/judge 规则命中**:系统性、可枚举的缺陷(auto 项规则 + [manual] 抽检),
   按 audit 输出批量修复。
3. **true_r 训练评测**:新失败模式 → 注册为新相似轴或新质量维度(§1 开放轴注册表)。

三者不互斥:失败 case 升格为 profile 规则后,就沉淀为来源 2;
来源 3 发现的新模式最终也以来源 1/2 的形式落地。

## 3. 检查清单

放量前对 pilot 产出逐项检查。标 `[auto]` 的由 `scripts/audit_embedding.py` /
`scripts/audit_vqa.py` 机器检测(规则来自领域 profile),标 `[manual]` 的需人工/agent 复核:

### 3.1 Embedding 线

- [ ] `[auto]` **正例文本 = query 世界观**:剥离 profile 污染词表命中的 shortcut 特征;核心内容 1–3 句,长度 ≤ `max_text_len`(默认 800)。
- [ ] `[auto]` **假负率抽检**:难负命中 profile `fake_negative_rules` 的比例(默认阈值 5%)。
- [ ] `[auto]` **资产路径有效**:引用的图像文件真实存在,且路径可被 profile `page_id_regex` 解析。
- [ ] `[auto]` **轴配比 = 几何权重**:各 similarity-axis 样本数量比决定向量空间被哪条轴主导。要么平衡采样,要么接受弱轴并靠推理期 metadata filter 补偿。
- [ ] `[manual]` **设计-实现缺口**:核对设计承诺的难负层级是否真的落地(极难负缺失会导致某条轴退化为字符串匹配)。
- [ ] `[manual]` **精确标识专项 eval**:业务上要求精确匹配的标识(编号、量值、代号)必须有专门评测 query,否则无法发现"模糊近似退化"。
- [ ] `[manual]` **Query 仿真度**:生成 query 应模仿目标系统真实用户,按轴均衡覆盖;
  **风格分布必须覆盖真实输入的长短/口语/术语混用**(全长句训练 → 短句 OOD,枢纽页有机可乘)。
  **量化验收**:[`audit_diversity.py`](../scripts/audit_diversity.py) 按 profile `diversity:`
  配额机检(长度三档/口语占比/distinct-n/每轴每源下限)——配额是本项的 `[auto]` 下限,
  人工复核在其之上补充语义层(术语用得对不对、指代清不清)。

### 3.2 VQA 线

- [ ] `[auto]` **Schema 对齐**:`images` 数 == `<image>` 标签数;最后一条消息是 assistant;答案非空。
- [ ] `[auto]` **答案泄漏**:答案子串出现在问题中的样本数(应≈0)。
- [ ] `[auto]` **答案长度**:超 profile 上限的占比(阈值 30% 告警)。
- [ ] `[auto]` **资产路径有效**:引用的图像文件真实存在,且路径可被 profile `page_id_regex` 解析。
- [ ] `[auto]` **来源配比**:各 `vqa_sources` 来源的数量分布,未知来源告警。
- [ ] `[manual]` **幻觉抽检**:抽样核对答案声称的图像内容是否真实可见(跨模态合法性判据)。
- [ ] `[manual]` **问题仿真度与多轮合理性**:问题是否覆盖真实问法、按来源均衡;多轮对话指代是否清晰。

### 3.3 通用

- [ ] `[manual]` 去重/封面过滤后样本数合理;成本日志在预算内;eval 切分遵守来源单元边界。
